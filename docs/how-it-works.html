How Mega Smart Context works

The host replays the whole conversation on every request. This plugin replaces that payload with three things the model can actually hold: a durable memory document, a short verbatim working window, and the current turn. Nothing in the durable transcript is ever rewritten.

This page describes the layout that ships today. The append-only redesign has its own design tour.

The one idea: context is a record the model maintains, not a transcript the host replays.

The model writes the durable half with smart_context. The pass derives the ephemeral half — the newest turns — from the host's transcript on every request. A turn that leaves the window is not lost: it waits in a pending queue, then goes cold in the archive.

1. One request, end to end

The pass runs on the host's context hook, before the request reaches the model. It reads the host's transcript, updates the session record, and replaces event.system and event.messages. The adapter then puts the smart_context tool on the wire.

Read it left to right

  1. The host hands over the whole transcript. Not the previous request — the durable conversation, rebuilt from storage. The plugin reads it and never writes it.
  2. The record is loaded first. The pass stamps the model, chooses the session's profile (manual pin, then model mapping, then default, then base), and applies that profile's caps to everything below.
  3. Only real user messages start turns. Injected megasc_ messages are dropped. Mode reminders and output-limit nudges are pulled out of the window and pinned into the system prompt instead, so they cannot inflate the window or age an eviction.
  4. The window is measured backward from the newest turn. The newest turns that fit workingTokens stay. The current turn is always kept, even if it alone exceeds the budget; that is reported as overBudget rather than silently cutting a tool result the model just requested.
  5. What left the window becomes pending. A turn gets a mechanical gist and its eroded raw messages. It ages only when a new user turn starts — a ten-call turn consumes one eviction lead, not ten.
  6. One memory block, one policy, one notices block. The memory document carries no live numbers, so its bytes change only when the model changes them. The policy is static for the same reason: a stable prefix keeps a provider's cache warm.
  7. Save, then send. The record is saved before the payload is handed back. The host's transcript is untouched, so the same pass can be retried and produce the same bytes.

2. What happens to a turn

A turn is a real user message and everything after it up to the next real user message. Because a tool call and its result live inside one turn, a cut can never separate them. The lifecycle below is the whole cold-storage story.

Age is counted in user turns

age increments only when the window's turn-id list changes. A ten-call turn is still one turn, so it consumes one eviction lead, not ten. With autoArchive on, a pending turn older than evictionLead is archived; with it off, the turn is dropped when the lead expires.

The gist keeps the decisive word

The mechanical gist keeps the first 120 characters of the user's own words and the last 40, with an ellipsis between them. A head-only cut once dropped the word a spec hung on. A model-written gist replaces the mechanical one. A manual archive is gist-only unless keepRaw:true; auto-archive keeps the raw as a safety net, so expand still works.

3. The two halves

The plugin has a server part and a terminal part. They share one RPC contract, but no storage: the server half owns the host KV record, and the TUI half keeps only an ephemeral mirror of the numbers it last pulled.

4. The memory document

The model's durable half is eight keys, always present, merged rather than replaced. A map merges key by key; a list replaces wholesale; null resets a key or deletes one map entry. A write over memoryTokens is rejected with the projected usage — the plugin never trims what the model believes it stored.

KeyShapeWhat it is for
goalstringThe user's request, written before the first turn leaves the window.
planlist of {step, status, text}The current plan; status is todo, active, done or blocked.
factsmapDurable things learned about the system, one entry per fact.
filesmapWhy a file matters, keyed by path.
decisionsmapChoices made and the reason, so they are not relitigated.
openlistOpen threads and next actions.
refslist of {page, section, gist, tokens}Feature-map pointers plus a one-line gist; cheaper than pasted prose.
notesstringAnything that does not fit the other keys.

5. The tool surface

One tool, nine actions. smart_context is a direct tool — call it by name, not inside execute. Every write goes through store.mutate, so a tool call and a context pass cannot lose each other's update.

ActionWhat it does
readReturns the pure memory document, or one key; no live numbers.
patchMerges only the keys named; maps merge, lists replace, null clears.
statsMemory/working usage, profile, turns kept/dropped, pending/archive/ref counts.
refStores a feature-map pointer and reports the gist vs section cost.
archiveMoves a pending turn to the archive with a gist; keepRaw:true keeps the raw.
purgeRemoves a turn; journaled so /undo can restore it.
recallSearches the archive; refuses without lost:true; returns matches + snippets.
expandPages a turn — pending or archived — with offset/limit or an outline.
noticeLists pinned host notices; retires a superseded one (never the newest).

6. The invariants that make it safe

  • The transcript is read-only. Every pass is re-derived from the host's messages plus the record. Nothing the plugin does edits history.
  • Bytes are stable. The policy is static, the memory block carries no live numbers, reasoning is passed through untouched, and erosion is a pure function of one message's own bytes. A completed turn's prefix does not change when the next turn arrives, so a provider's prefix cache stays warm.
  • A cut is a turn boundary. A turn starts at a real user message; a tool call and its result can never be separated. Mode notices, jobs and resume cues are not turns.
  • The first pass only seeds. Enabling the plugin mid-session does not evict turns it never managed.
  • Nothing is irrecoverably lost by default. An unhandled pending turn auto-archives after the lead; recall is gated by lost:true so the archive stays cold; expand can read a turn before the model decides.
  • Every session is independent. A subagent has its own record. A child may read the parent's archive with from:"parent", but every writing action stays on its own session.
  • The TUI cannot see the KV. It reads through the server's RPC and keeps an ephemeral mirror; the RPC names the terminal's location, because the host routes plugin RPC by location.
