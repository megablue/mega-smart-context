Capture guarantees - directives survive, phase stays visible

Status: shipped (v0.3.22) - Read when: a user says "remember" or "don't", the plan disappears after a host compaction, directives, the phase line in the state note, runCompaction recovery, or "the model forgot what I told it".

What it does

  • Copies every user sentence that states a standing instruction (remember, don't forget, never, always, from now on, do not, must, only, make sure) into the memory document verbatim, so it survives the working window and both compaction paths.
  • Names the current plan phase in the state note on every pass: the active step and the done/total count.
  • After a host compaction, reports what survived; when no plan survived, tells the model to recover it from the archive before continuing.
  • Lets the model clear a directive once it has folded it into decisions, so the list does not become a second memory.
  • Names a list that shrank in the patch reply, so a partial plan, open, refs or directives patch cannot delete entries silently.
  • Adds one capture: line to the state note after eight completed tool calls with no accepted write in the turn.
  • Keeps the runtime as the schema owner: the capture is extraction and retention, never summarization.

How & why

The two moments memory misses

A standing instruction lives only in the user message. It leaves with the working window, and a host compaction replaces the transcript with renderMemory(record); if the instruction was never written, it is gone. The same is true of the plan: the assistant's plan message is transcript, not memory.

The plugin's own fold has a commit window ("compaction due", the leaving turns, a turn to write). runCompaction has none: the host decides, the hook returns the memory document, and the transcript is replaced. A feature that relies on the model writing at that moment cannot work, so capture has to happen on the pass, mechanically, before the model is asked anything.

Directives: verbatim, mechanical, bounded

directivesIn splits a user message into sentences, strips host blocks (<system-update>, <system-reminder>), drops questions, and keeps a sentence only when it matches an explicit instruction marker. The sentence is trimmed and capped at MAX_DIRECTIVE_CHARS; no paraphrase and no merge. A directive that repeats an existing one (case-folded, whitespace-collapsed) is not added again.

captureDirectives runs in buildAppendPlan over the raw messages from the window start, before the payload is rendered, keyed by the turn id. It is idempotent, so the several passes of one turn add nothing after the first. The list is capped at MAX_DIRECTIVES; when full, the oldest entry is dropped and the render says how many were dropped, so the loss is visible rather than silent.

The entry renders inside the <smart-context> block as ## Directives, after the goal and before the plan, once the checkpoint carries it: a fold copies the merged document into base and a host compaction returns it. A directive captured after the last checkpoint is not yet in the block the model just read, so the tail state note names it under directives: captured since the checkpoint until the next fold. The tail is the one part allowed to churn, so a new directive changes no cached bytes before it; a long session with no directive keeps the block stable.

The model clears an entry with an ordinary patch (directives: [] resets the list, or a rewritten list keeps the rest). Lists replace wholesale, so a partial list is a deletion; the same trap as plan and open, and the shrink warning applies to it too.

Plan and phase

The phase is derived, not stored twice: the first step with status active is the current unit, and the note prints phase 2/6 active: <text>. With no active step it prints phase: none active (plan 2/6); with no plan at all, phase: none (plan empty). It is rendered in the tail state note, so it costs no prefix stability and is impossible to miss.

At the plugin's due mark the same line is added next to the leaving turns, so the commit window is about state as well as turn ids. If the plan is empty at that point the note says the fold will keep no phase information.

Post-compaction recovery

runCompaction already stores record.hostCompact with the time and the archived count. The note extends it: when the plan is non-empty it repeats the phase; when it is empty it says the transcript was replaced with memory, that no plan or phase survived, and that the archived turns are searchable (recall with lost:true, then expand). That turns a silent loss into a named next action.

Feedback at the write moment

A patch that shrinks a list replaces it wholesale, so the reply appends plan: 7 → 2 item(s) — lists replace, send the full list if that was not intended. The same applies to open and refs. For directives a partial drop is named, while a full clear (directives: []) is the contract and is not warned.

The no-write cue is the other half: when the current turn has made CAPTURE_CUE_CALLS (8) completed tool calls and has no accepted patch for that turn, the tail note prints capture: N calls this turn, no accepted patch — record what matters.... It is a reminder, not a rejection; an accepted patch for the turn removes it on the next pass. The count comes from the turn span's tools, so it survives the window being rebuilt.

Traps

  • Do not summarize the directive. The value is that it is the user's own words; a paraphrase is the model's memory again and can drift.
  • Do not capture the assistant's plan text. Extraction of arbitrary prose is unreliable; the plan is model-authored on purpose, and the fix for a missing plan is the phase line plus the fold warning, not a parser.
  • cloneMemory must copy every key. The checkpoint is an explicit copy; a memory key it forgets renders in the merged document and disappears at the next fold. Pinned by "the checkpoint clone keeps a directive".
  • Clearing must dismiss. Capture re-reads the same turn on every pass; a cleared directive that is only removed from the list would reappear next pass. The removed sentence is recorded in directivesDismissed, keyed by turn and text, so the turn stays clear while a later turn that repeats the sentence is captured again. The cap drop uses the same key.
  • Capture before render. If the pass renders first, the directive appears one pass late, which is exactly the pass that may be compacted.
  • Idempotence. A turn produces several passes; the turn id plus the normalized text is the dedupe key, not the message index.
  • The directive list is not a second working set. Clearing it after folding into decisions is part of the contract; the policy says so and the cap enforces it.
