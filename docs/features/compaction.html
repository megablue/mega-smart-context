Compaction - one document, one checkpoint

Status: shipped (v0.1) - Read when: the compaction hook, runCompaction, a host checkpoint, or "the summary and the memory disagree".

What it does

  • Answers the host's compaction request with the rendered memory document, so no second summarizer runs.
  • Declines when memory is empty and lets the host summarize.
  • Never writes event.messages; the transcript is read-only here too.
  • In the append layout, also folds the update log into a new checkpoint on action:"compact" or at the prompt after the shared pool fills, then keeps the newest compactKeepTokens of turns and archives the rest; with rebuildOnCompaction, also rebuilds the retained tail's bytes (reasoning dropped, write/edit calls and results shortened to the path, long shell output tail-kept, grep previews reduced to line numbers, repeated reads marked, errors kept).

The user-visible behavior is in docs/SPEC.md under "Compaction".

How & why

The seam

The host calls the compaction hook with the transcript it is about to summarize. Setting event.result = { summary } makes the host persist that string as the compaction message and skip its own model call. runCompaction sets it to renderMemory(record) when the record's memory is not empty.

This is the same block the next request will carry, minus its live counters - the block has none. A checkpoint and a working memory that disagree are worse than either alone, and a second summarizer would be a second source of truth.

Why decline on empty

An empty memory document is not a summary. Returning it would replace a real checkpoint with an empty block and lose the transcript's content in the name of owning it. isMemoryEmpty checks every key; when it is true, runCompaction returns undefined, the host's own summarizer runs, and nothing is lost.

The append layout's reset

The host hook and the append reset are different seams. The hook answers a host checkpoint with renderMemory(record), the merged document. The append reset is the plugin's own: action:"compact" asks for it immediately, and a full shared pool sets compact.due — a commit window, not an order to fold at once. The mark records the current turn; every pass of that turn keeps the window open (a real context window has room the estimated pool does not), the note lists the turns that will leave, and the fold runs on the first pass whose current turn is newer: the next prompt.

The reset makes base = memory, clears updates, and clears the mark. It keeps the newest turns that fit compactKeepTokens (20k by default) — not the working share, which would keep almost everything and free nothing — and archives the rest immediately with their raw messages: the commit window was the model's chance to summarize them into memory, so they do not sit in a pending queue begging to be purged. windowStart moves to the first retained turn. This is the one intentional cache reset in the append layout; a patch and a longer window only append.

What the rebuild rewrites

With rebuildOnCompaction, the fold also rewrites the bytes of the completed retained turns, because the cache is already cold there. Reasoning is dropped; a successful write/edit call keeps only its path (the body is on disk and the result already confirmed it) and its text result becomes <path> ok; a long successful shell result keeps its last 20 lines; a grep result keeps the files and matched line numbers and drops the quoted lines; a read a later read of the same path repeats becomes a one-line marker. Only a same-range or whole-file read replaces an earlier one, and a write or edit in between clears the chain, so a pre-edit copy stays. Error results, content/json shapes, unknown tools, user text and the current turn are untouched, and a call and its result are never separated.

Type and safety notes

CompactionEventLike has a mutable result and index signature because the source assigns to the host's event. event.messages is typed as readable and is never written. An error in the hook is caught in index.ts and turned into a decline, so the host still summarizes.
