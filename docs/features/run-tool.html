Run tool - one shell with a clock that fits the work

Status: shipped (0.3.17) - Read when: run, PersistentShell, JobRegistry, TimingStore, classify, resolveNpmScript, .opencode/run.json, the host shell is replaced, or "the command was killed at the timeout".

What it does

  • Removes the host's shell tool from the registry and the offered set and offers run in its place; a before-execute guard rejects any stale shell call with a use-run error. The model calls run through Code Mode and gets output, exit code, wall time, state and an optional job id.
  • Quick commands return as soon as they exit. The persistent PowerShell REPL starts on the first call and is reused, so later quick calls are tens of milliseconds rather than a new process.
  • npm run <script> starts the package script directly, so it does not sit in the npm wrapper's start-up window; pre/post scripts and extra arguments stay on npm.
  • On Windows the shell and job children share the host console when the host has one, so node/npm/vite grandchildren cannot allocate a new visible console and steal focus; otherwise the job/service child gets a hidden console that its node/npm/vite descendants inherit, so no visible console is allocated and focus is not stolen. The persistent shell remains on windowsHide: true.
  • A host plugin reload does not abort an in-flight run: the shell finishes the current command before it stops, and running jobs keep running.
  • One-shot git push/fetch/pull are quick commands and return their output; only git clone stays a job.
  • The shell reports an up-to-date git push as success; PowerShell's $LASTEXITCODE is -1 for that case.
  • Servers and watchers return a job id as soon as a manifest rule or a built-in pattern says they are ready; they keep running.
  • Builds, tests, deploys and CI watches wait for the learned p90. If they overrun, they return a job id, keep running, and send a completion note.
  • Nothing is killed on a deadline. timeout is an expected-duration hint; job plus stop:true is the explicit stop.

  • src/core/run/classify.ts - classify, readManifest, CommandClass, RunManifest, ServiceRule. Built-in service/job patterns and the project manifest.
  • src/core/run/shell.ts - PersistentShell; prewarm, run, dispose. A long-lived PowerShell REPL.
  • src/core/run/jobs.ts - JobRegistry, JobResult; start, status, stop, dispose. Session-scoped job ids, output capture and the completion note.
  • src/core/run/timings.ts - TimingStore; signature, project, p90, deadline, record. The learned clock table.
  • src/core/run/tool.ts - TOOL_NAME, TOOL_DESCRIPTION, TOOL_INPUT, TOOL_OUTPUT, createRunTool.
  • src/core/run/npm.ts - resolveNpmScript, npmScriptCommand, NpmScript. Resolves an npm run script to its package command and the npm lifecycle environment.
  • src/core/run/windows.ts - consoleSpawnOptions. Shares the host console when there is one; otherwise gives the child a hidden console so descendants inherit it.
  • src/adapters/opencode/index.ts - creates the shell, jobs and timing store; registers the tool; removes shell from the tool registry via ToolEditor.remove when the host supports it; adds the context hook that deletes event.tools.shell and inserts run; registers a tool.execute.before guard that denies a stale shell call; disposes the shell and jobs.
  • .opencode/run.json - optional per-project services and jobs rules, read by readManifest.

How & why

The host's shell tool has no clock: a dev server either blocks the turn or gets killed at the deadline. The run tool makes the clock part of the classifier. classify checks the project manifest first, then the built-in service patterns (Vite, Next, uvicorn, Flask, dotnet, Rails, ...) and job patterns (npm test/build/deploy, jest, vitest, tsc, gh run watch, git push, docker build).

A quick command goes to the persistent shell with no timeout. The first call pays the PowerShell start; later calls reuse the shell. Output is capped at 8,000 characters with a head/tail and a job hint so a large log cannot swallow the turn.

npm run <script> is resolved from the project's package.json and run directly with the npm lifecycle environment and node_modules/.bin on PATH. The wrapper's start-up is long enough for a host plugin reload to dispose the shell; the direct script finishes first. Pre/post scripts and extra arguments stay on npm.

On Windows windowsHide alone gives the top-level PowerShell no console, so console-app grandchildren can allocate a visible console and steal focus. windows.ts shares the host console when the host has one; otherwise the job/service spawn combines detached: true with windowsHide: true so the child gets its own hidden console. The persistent shell stays on windowsHide: true; detached breaks its stdin REPL.

The adapter's disposer no longer rejects a pending shell command; it marks the shell for shutdown and stops it after the result. JobRegistry.dispose forgets the jobs without killing them, so a service survives a plugin reload.

The learned deadline can be zero for a new signature. The job path waits at least 2s before returning a running job, so a short command's output arrives in the same call.

Git one-shots were classified as jobs, so git push returned an empty completed result. Only git clone is a job now; the rest use the quick shell's 10s clock.

A successful up-to-date git push leaves $LASTEXITCODE at -1. The shell treats -1 as success when the command did not throw, so the call is completed rather than failed.

A service starts under JobRegistry; the registry returns a job id as soon as the manifest's ready text or port appears, or after the ready timeout. A job uses TimingStore.deadline: the learned p90 times 1.5, floored at 30 seconds and capped at 30 minutes, raised by a larger timeout hint. If the deadline passes, the call returns the job id and the registry keeps the process alive; a completion note is delivered with ctx.session.synthetic.

job reads the status, job plus stop:true stops it, and both are scoped to the calling session. An unknown id is an error, not another command. The adapter removes shell from the tool registry (ToolEditor.remove), the context pass deletes it from the offered set, and a tool.execute.before guard denies a stale shell call with an error that says to use run. The transcript is untouched.

Config keys / UI

No plugin config keys. The optional project manifest at .opencode/run.json:

KeyTypeMeaning
services[].matchstringRegex (or case-insensitive substring if the regex is invalid) matched against the command.
services[].readystringText to wait for in the service output.
services[].portnumberPort to probe for readiness.
services[].readyTimeoutMsnumberHow long to wait for readiness before returning the job.
jobs[]string[]Commands (substring match) that should use the learned job clock.

Tool input: command, workdir, timeout (hint), job, stop. No UI; the tool is offered in the Code Mode catalog and in the context payload.
