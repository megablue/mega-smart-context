Project facts - learned microskills from observed outcomes

Status: implemented (0.2 line) - Read when: project.ts, facts.ts, facts-learn.ts, project-session.ts, a project key or worktree key, ProjectStore, the fact lifecycle, renderFacts, /context facts, redaction, or "a fact was learned that should not be".

What it does

  • Stores short, evidence-backed environment facts per repository, shared by every worktree of one git root.
  • Learns only from a tool call paired with its observed result: command, exit code and a canonical error signature. Assistant prose and raw output are never inputs.
  • Promotes a candidate after K_PROMOTE = 3 confirmations from separate sessions, then injects it only after it clears the firing gate.
  • Renders a deterministic block capped at 4 facts and 150 estimated tokens, with the fact id beside each claim so it can be forgotten by hand.
  • Keeps facts inspectable and forgettable. A forgotten or retired id is never learned again; unforget restores a forgotten record.

The pure modules are wired through src/core/project-session.ts and the session.context seam. The first pass renders the block once and stores a per-session snapshot; later passes reuse it byte-for-byte. The OpenCode adapter resolves the git root, keeps one ProjectStore per setup, and /context facts lists, forgets and unforgets facts.

How & why

Key

projectKeyFor({ directory, gitRoot }) picks the git root when present, otherwise the canonical directory. Both are normalized: backslashes become /, duplicate and dot segments collapse, a trailing slash goes, and an absolute Windows path is lower-cased. The key is hashed with SHA-256 and stored under project/<hash>. Worktrees therefore share facts; a different drive or POSIX path does not.

Lifecycle

applyEvidence creates a CANDIDATE on first sight. A confirmation from the same session is counted once, so two turns in one session cannot promote a fact. At K_PROMOTE distinct-session confirmations it moves to facts and becomes ACTIVE. The recency score is sum(0.8^age) over confirmations minus 5.0 times the same sum over contradictions; an ACTIVE fact below SCORE_FLOOR retires. A high-stakes family (absent_tool, boundary) retires on one clean contradiction under HARD_KILL.

Firing gate and render

An ACTIVE fact is injected only when fireDen >= 4 and fireNum / fireDen >= 0.40. A session is counted once for exercise and once for firing. renderFacts sorts by id (never by score or insertion order), includes whole bullets only, drops the header when no fact fits, and clamps caller overrides to 4 facts and 150 estimated tokens. Two passes over the same record are byte-identical, which is what keeps the provider prefix stable.

Learning

extractObservations pairs tool-call with tool-result by id and ignores a call with no result. Shell tools yield a redacted command, an exit code and a signature such as command not found, module missing, connection refused, dns failure, usage error or env:NAME. foldObservations dedupes by session+turn fingerprint and derives only these families: absent tool, form repair (failed form then a later working form with the same command form), boundary, env value (failure plus a later working form) and empty git discovery probe. arg_repair has the lifecycle and render support but no automatic extractor yet.

Privacy and forgetting

redactText removes home paths, URL userinfo, query-string secrets, key/value secrets, bearer tokens and common token shapes. An observation stores no output field at all; only a signature, a host name and an environment variable name can survive. forgetFact moves the record to retired with reason forgotten; applyEvidence refuses that id forever; unforgetFact restores it. Candidates and retired facts expire after 90 days and are bounded by MAX_CANDIDATES and MAX_RETIRED.

Store

ProjectStore mirrors SessionStore: per-project cache, per-project mutate lock, and an optimistic updatedAt guard. A stale save returns false and adopts the stored copy; mutate reruns its callback once on that copy and then throws ProjectStoreConflictError. A storage failure is logged and the in-memory copy remains.

Implemented command surface: /context facts lists rows from describeFacts and the block renderFacts would inject; /context facts forget <id> calls forgetFact; /context facts unforget <id> calls unforgetFact. A status row can later show facts N (M injected) and renderFacts(...).tokens.

The session snapshot is projectFacts?: { version, key, ids, rendered, tokens, at } on SessionRecord. The plan's shorthand record.facts is ambiguous because record.memory.facts already exists; the distinct field name is used. The first pass of a session loads the project record and stores this snapshot; every later pass reuses rendered byte-for-byte, so a fact learned mid-session reaches the next session, not the current one. factsFolded records the newest completed turn whose observations were folded; the live turn is never folded.

Tests that pin it

All in scripts/project-facts.test.mjs; run node scripts/project-facts.test.mjs. No network and no model calls.

  • project key normalizes drive case and separators
  • a worktree shares the git root key
  • the project record carries the documented JSON shape
  • the store merges independent mutations / a stale save is refused and the stored record wins / mutate retries once on a concurrent write
  • K=3 confirmations across separate sessions promote a candidate
  • the fire gate holds an ACTIVE fact back until four exercises
  • recency decay lowers the score and a later contradiction retires a non-high fact
  • a high-stakes contradiction retires at once
  • forget hides a fact, blocks re-learning and unforget restores it
  • the render cap is four facts and 150 estimated tokens, hard / render is stable across passes and insertion order
  • redaction removes secrets, credentials and home paths / extraction parses a signature but never stores raw output
  • a shell failure becomes a candidate and three sessions promote it / a working tool contradicts an absent-tool fact and retires it
  • a later working form repairs the failed form / facts folding leaves tool usage to the usage fold
  • Smoke: first-pass injection and second-pass byte stability; no block without the project layer or with projectFacts:false; fold-once across repeated passes; /context facts and forget clearing the snapshot
