## State

- **The feature map is HTML, and the ref reader reads both formats.** `docs/features/` now holds `index.html` plus one `.html` page per feature; the Markdown sources were pruned. `src/core/refs.ts` resolves a page to candidates (`pageCandidates`: `.html` before `.md` for a bare name, the named file first when an extension is given, the sibling second) and `htmlToText` flattens an HTML page into Markdown-shaped text so the same `extractSection` runs over either. The HTML section costs ~97% of its Markdown twin. Pinned by 12 new smoke assertions; `feature_map_check` reports 9 rows / 9 pages.
- **v0.1 is implemented and the gate is green.** `npm run typecheck` passes; `npm run smoke` prints `smoke: 179 assertions passed`; `npm run test:install` prints `install smoke: 17 assertions passed`; `npm run version:check` passes.
- **Host mode notices are pinned, not replayed as turns.** The host admits a Plan/Build switch as a synthetic *user* message holding a `<system-reminder>` block; counted as a turn it inflated `workingTurns` and, worse, changed the window's turn-id list so a mode switch aged a pending turn the model never saw. `splitNotices`/`noticeOf` (`view.ts`) strip those messages before `turnSpans`; `upsertNotices` (`state.ts`, `MAX_NOTICES` 8, 4000-char head-keep) keeps every distinct text, and `renderNotices` pins them into one system part after `POLICY`, newest first. `smart_context action:"notice"` lists them and `remove:"<id>"` retires a superseded one; the newest is refused. **Two rail defects found live and fixed:** the list order is now *recency of emission* (a text the host re-emits moves to the end; first-sight order froze and made the rail protect the stale build text while allowing the live plan text), and a removal now writes `record.retired` (bounded by `MAX_RETIRED` 32) so the next pass skips a text whose newest occurrence id is retired instead of re-adding it; the same text under a new id clears the retirement and returns. Pinned by 31 + 13 new smoke assertions (146 total). See `docs/features/context-handoff.html`.
- **Host messages that are not turns: a job is annexed, the output-limit nudge rides the notice rail.** `hostMessageOf` (`view.ts`) is the single classifier for the synthetic *user* messages the host injects (role `user`, one text part, a trailing `@n@` stripped). A mode reminder and the output-token-limit nudge are *notices*; a `<shell>`/`<subagent>` completion is a *job*. `isRealUser` now excludes a job, so it annexes to the newest span: its bytes stay in the window and count toward that turn's budget, and it ages no pending eviction (the work it reports is work the model already asked for). The nudge reaches the existing rail unchanged - pinned, listed by `action:"notice"`, protected by the newest-refusal. The host's own instruction set, which rides in `event.system` beside `POLICY`, is measured display-only (`hostSystemTokens`/`hostSystemParts` on `lastReport`/`PassSample`) and printed by `/context` as `host system ~X est (N parts)`; with `debug` on the pass also logs the count and the head of each part, which is how `event.system`'s shape is checked. Pinned by 24 new smoke assertions (170 total). See `docs/features/context-handoff.html`.
- **The outbound prefix is now byte-stable per message, by three fixes (v0.1.14).** (1) The memory block no longer renders a live `budget:` line - a line that changed on every pass - so the block changes only when memory does; the numbers moved to `smart_context action:"stats"` and `/context` (`renderMemory(record)`, no `report` param; `read` with no key is the pure document). (2) A window message is never rewritten once sent: the `stripReasoning` pass and its `keepFromIdx` "keep only the current turn's reasoning" rule are gone, so reasoning reaches the model exactly as the host sent it; `erodeToolResults` is a pure function of the message's own bytes. (3) The pinned-notices system part stays last in `system` and is never reordered, so a mode switch appends rather than moves. Pinned by smoke: "the memory block carries no budget line", "the memory block is byte-identical when only the window grew", "reasoning is kept in the payload", "a completed turn's bytes do not change when the next turn arrives", "the pinned notices are the last system part". The remaining cracks are not per-message: `## Pending eviction` changes when a new turn evicts one, and a memory write changes the block. See `docs/features/context-handoff.html`.
- **The live run exposed one real bug, fixed and running in the installed copy.** A tool result whose `result.type` is `content` (a multi-part result, e.g. two text blocks) was eroded by writing a string into `result.value`. OpenCode's `SessionModelRequest.prepare` maps over that array (`l.value.map`), so every continuation of that turn failed with **"session failed: l.value.map is not a function"**. `erodeToolResults` now shrinks only the text parts and keeps the array; `json` results are left untouched. Pinned by smoke assertions. It went live in the 22:11 restart; the loaded copy has carried it since.

## Known gaps (volatile; the durable traps live in the feature pages)

- **The smoke is not the host.** It exercises the transform, the tool, the archive, subagents, compaction and the installer through a fake `ctx`. The live run found one shape mismatch the fake host hid (`content` tool results); assume other shapes can differ too.
- **`/context` delivers through `ctx.session.prompt`.** That creates a user message, which the next context pass treats as a real turn. It does not corrupt memory, but the command's report can become part of the conversation it is reporting on. There is no display-only channel: `ctx.session.synthetic` still starts a model turn (probed live), so `prompt` is the honest choice.
- **A child's archive survives until the store's LRU evicts it** (`MAX_SESSIONS` 64). There is no per-child cleanup on session end. The startup sweep only removes records whose session the host no longer has; records for sessions that still exist are never capped on disk.
- **The archive caps are per session** (`archiveMaxTurns`, `archiveMaxChars`); there is no global storage budget.
- **The ref reader uses the session directory's `docs/features/`.** A bare page name tries `<name>.html` then `<name>.md`; an explicit extension tries that file first and its sibling second. An HTML page is flattened to Markdown-shaped text (`htmlToText`), so `extractSection` runs over either format; `refs.md` written by an old session still finds `refs.html`. The loaded build now contains it (v0.1.10), but no ref has been taken since the restart, so the HTML path is still unexercised live. A worktree without that directory reports "section not found" but still stores the pointer.
- **The install is a copy.** Editing the source tree does not update an installed copy; run `plugin:install` again, and the host picks it up at the next pass. `plugin:status` reports the drift.
- Environment note: this shell is Windows PowerShell 5.1 - no `&&` (a parser error), chain with `;` and check `$LASTEXITCODE`. `Get-Content` can render UTF-8 punctuation as mojibake, so verify a written `.md` with a `node -e` UTF-8 read rather than trusting the console.
